1. EXECUTIVE SUMMARY & PROJECT OVERVIEW
================================================================================
An industry-grade, cutting-edge 3D developer portfolio and real-time interactive web experience. Unlike standard static resume websites, this application combines high-performance full-stack web engineering, 3D spatial computing, real-time WebSocket multiplayer networking, and buttery 60 FPS GPU-accelerated micro-interactions.

The project features:
• An interactive 3D mechanical keyboard scene where each keycap is mapped to a technology, reacting in real-time to physical key presses and mouse hover events with realistic acoustic feedback.
• Real-time multiplayer synchronization via Socket.IO, displaying live remote cursors of concurrent visitors and an interactive radial reaction wheel that broadcasts emoji confetti bursts across networks.
• A high-performance, GPU-composited Project Details Modal with interactive screenshot slideshows, zoomable lightboxes, and smooth inertia-based scrolling.
• A serverless contact system powered by Next.js Route Handlers, Zod schema validation, Resend email API integration, and direct two-way email reply routing.
• Zero-compromise web performance: 60 FPS render loops, hardware-accelerated transforms, Lenis smooth inertia scrolling, and sub-second cold starts on Vercel edge networks.

5. INTERVIEW TALKING POINTS & TECHNICAL DEEP DIVE
================================================================================

Q: "How did you synchronize the 3D scene with the page scroll?"
A: "I integrated the Spline runtime with GSAP's ScrollTrigger. By creating custom timelines for each section trigger (Hero, Skills, Experience, Projects, Contact), I updated the 3D camera coordinates, rotations, and target lookAt vectors continuously based on the user's scroll percentage. This keeps the 3D mechanical keyboard smoothly animating in space as you travel down the page."

Q: "How did you solve the modal lag and scrolling conflict?"
A: "The modal previously had frame drops caused by two main bottlenecks: animating CSS backdropFilter with Framer Motion on every frame (forcing continuous GPU rasterization) and rigid nested scroll components fighting the page's smooth scroll. I resolved this by decoupling the backdrop blur into a static CSS class on the overlay and animating only opacity, which is 100% GPU-composited. Then, I added Lenis scroll prevention (`data-lenis-prevent`), `overscroll-contain`, and native hardware acceleration (`transform-gpu`), yielding butter-smooth 60 FPS opening transitions and fluid mouse wheel scrolling."

Q: "How does the real-time cursor feature work without lagging the client?"
A: "Real-time cursors use Socket.IO over WebSockets. If you broadcast every single mousemove event, it saturates network bandwidth and causes event queue buildup. I implemented a `useThrottle` hook that caps coordinate emission to 200ms deltas, transmitting lightweight payload objects containing only `{ pos: { x, y }, socketId }`. On the client, Framer Motion handles smooth interpolation between coordinate updates so other users' cursors glide smoothly across the screen without jitter."

Q: "How is email delivery handled securely in production?"
A: "I built a dedicated Next.js Route Handler at `/api/send` configured with `force-dynamic` to ensure Vercel executes it as a serverless function. Inbound payloads are validated against a Zod schema to prevent malicious or malformed inputs. The route communicates with Resend's API using `process.env.RESEND_API_KEY` stored securely in environment variables (preventing secret leaks in git). Critically, I mapped `replyTo: zodData.email` so that when a visitor sends a message, clicking 'Reply' in Gmail opens a direct thread with that user."
